# 42 — MRT2: a pattern clip played by Magenta RealTime 2

*Render with MRT2…* plays a pattern clip's notes through Google
DeepMind's [Magenta RealTime 2](https://huggingface.co/google/magenta-realtime-2)
(MRT2) and puts what it plays on a new audio track under the clip. The
notes say which pitches sound and when; a text prompt says what plays
them ("solo grand piano, warm", "west coast hip hop, deep bass"); a seed
picks one performance, the same one every time.

**Status:** draft, built 2026-10-17 on branch `mrt2-generate`: the pack
(§The pack), the renderer (§The renderer) and the menu item and dialog
(§Render with MRT2). Linking the model into slab for live playing is
§Later.

Code:
- `src/mrt2.zig`: the clip as MIDI, the renderer as a child process
- `src/ui/mrt2_dialog.zig`: the dialog
- `placeMrt2`, `openMrt2` in `src/main.zig`
- `tools/mrt2/mrt2.py`: the pack's importer
- `tools/mrt2/native/`: `mrt_render`, on upstream's `magentart::core`
- `packs/mrt2.pack.json`

## The model

MRT2 is a live music model: it makes audio one 40 ms frame at a time
(25 frames a second, 48 kHz stereo) from three inputs.

- **Style:** a MusicCoCa embedding of the prompt text, tokenized.
- **Notes:** for each frame, which of the 128 MIDI pitches are held, and
  whether each just started. A note shorter than a frame still counts
  as an onset. There is no velocity. Pitches 128–131 are four drum
  triggers.
- **Context:** the audio tokens it made in the last ~20 s.

Two sizes: `mrt2_small` (230M parameters) and `mrt2_base` (2.4B). The
pack installs small. It renders at about real time on a base M2. Base
sounds better, needs an M2 Max or M4 Pro for real time, and is 2.8 GB
more.

The sampler's random keys come from `42 + seed` at reset
(`MLXEngine::set_seed_rotation`). Measured 2026-10-17: two renders with
the same notes, prompt and seed were byte-identical, and a different
seed gave a different take.

## The pack

`packs/mrt2.pack.json`, a download pack whose importer is
`tools/mrt2/mrt2.py` (docs/25 §Installing). It installs into
`<library>/mrt2/`:

| Folder | What |
|---|---|
| `models/mrt2_small/` | the exported model (`.mlxfn`) and its initial state |
| `resources/` | MusicCoCa (TFLite) and SpectroStream, shared by both sizes |
| `bin/` | `mrt_render`, with MLX's dylibs and `mlx.metallib` beside it |

The importer:
- **Downloads** twelve files from Hugging Face at a pinned revision
  (1.8 GB), each checked by SHA-256. `--from DIR` copies them from an
  existing Magenta RT 2 folder instead, such as the apps'
  `~/Documents/Magenta/magenta-rt-v2`.
- **Builds `mrt_render`** in `<home>/Cache`. uv makes a Python for
  `mlx-metal` and CMake. MLX comes prebuilt from the wheel, so Xcode's
  separate Metal toolchain isn't needed. Upstream's engine, TFLite and
  SentencePiece build from source.
  - Measured 2026-10-17 on a base M2: about 16 minutes at 4 jobs the first
    time, with 2 GB in the cache, almost all of it TFLite.
- **Pins MLX at 0.31.2.** 0.32 can't load the published `.mlxfn` exports
  (magenta/magenta-realtime#103).
- **Checks** that `mrt_render` renders a second of audio, then moves
  `models/` into place last. Slab counts a model pack installed once
  `models/` exists.

## The renderer

`mrt_render` is about 250 lines over upstream's `magentart::core`:

```
mrt_render <model.mlxfn> <resource_dir> -o out.wav [--midi in.mid] [--seconds S]
           [--prompt TEXT] [--seed N] [--tail S] [--temperature T] [--top-k K]
           [--cfg-musiccoca X] [--cfg-notes X] [--onset-mode 0|1] [--transpose N]
```

- **MIDI in:** a Standard MIDI File, format 0 or 1, with the tempo map
  merged across tracks. Channel 10 is skipped, since its note numbers
  name drums.
- **Frames:** every note event inside a frame's 40 ms conditions that
  frame.
- **Onsets:** onset mode 1 tells the model where notes start; a score
  knows exactly.
- **Length:** `--seconds` with `--midi` sets the length. Without it the
  render runs to the last note plus `--tail`.
- **Out:** 48 kHz stereo float32 WAV. A `rendered N of M s` line goes
  to stdout once a second.

Measured 2026-10-17 on a base M2 (24 GB):
- **Speed:** 22–36 frames a second when the machine was otherwise
  quiet, and 6–12 under heavy load.
- **Warm-up:** the first run after install compiles Metal shaders
  (about 45 s). After that, a render starts in a few seconds.
- **The notes steer it:** a four-bar test score (Am, F, C, E) was
  rendered with a piano prompt. The three strongest pitch classes in
  each bar matched the bar's chord tones in 11 of 12 cases. With the
  same prompt and seed and no notes, 4 of 12 matched.

## Render with MRT2

The item is in the arrangement's clip menu, enabled when the focused
clip is a pattern with notes.

### The dialog

`mrt2_dialog.zig`:
- **PROMPT:** what plays the notes.
- **SEED:** a whole number. The same notes, prompt and seed give the same
  audio.
- **RENDER:** writes the clip's notes as MIDI and starts `mrt_render`.
  Without the pack the dialog says to get it and RENDER does nothing.
- **While it runs:** the renderer's last line and CANCEL, which stops
  it (SIGTERM).

### Timing

The clip's notes go to MIDI at one tick a millisecond, at 60 BPM. Each
note's time is `map.secondsAt(clip start + note start)` minus the
clip's own start, so tempo changes and ramps under the clip are baked
into the ticks. Notes are cut at the clip's end. The render runs for the
clip's length plus 2 s (`TAIL_SEC`), for the release.

Not yet:
- **Polytempo:** the track's polytempo rate (docs/28) and groove
  (docs/29) don't move the notes.
- **Expression:** pitch bends and pressure are dropped; the model has no
  input for them.

### What it makes

`placeMrt2`:
- **The file:** `<clip>-mrt2-seed<N>.wav` in the project's `audio/`
  folder, or `<home>/Cache/recordings` for an unsaved project, which the
  next save collects.
- **The track:** a new track right under the clip's track, routed where
  that track goes, holding one audio clip that starts at the pattern
  clip's start beat. Its length is the WAV's duration at the song's
  tempo.
- **The original:** the pattern clip stays as it is and keeps playing.
  Mute it to hear the render alone.
- **Undo:** one step.

One render runs at a time. Quitting slab stops it.

## From slabkit

A song script does the same with `Clip.mrt2` (tools/slabkit):

```python
c = keys.clip(chorus).chords("Am F C E", "x...x...x...x...")
c.mrt2("lush analog synth pads, 80s synthpop", seed=3)   # a track under KEYS
```

It follows the menu item's timing (§Timing), runs `mrt_render`, and
places the WAV with `Track.audio` on a new track right under the clip's,
at the clip's start. A render is keyed by its notes, prompt, seed and
length and kept in `<home>/Cache/mrt2/`. A script re-run reuses it, so
the song stays reproducible without rendering again. It warns when the
track has a tempo ratio.

## Why a child process

Slab runs `mrt_render` the way it runs pack importers (`posix_spawn`,
output to a log, `waitpid` each frame):

- **Slab's build doesn't change.** MLX, TFLite and SentencePiece stay
  out of `build.zig`. Linking them would add a CMake build of
  TensorFlow Lite to every slab build, including for people who never
  install the pack.
- **A crash stays outside.** A model failure or out-of-memory can't take
  the audio thread down.
- **It's swappable.** A CoreML renderer (§Later), or `mrt2_base`, is
  another binary with the same arguments.

The cost is loading the model for each render, a few seconds against a
render that takes as long as the clip.

## Later

- **Playing it live:** link `magentart::core` behind a build option, as
  a machine that hears the track's notes and plays into the graph. This
  needs the frame loop on its own thread (`RealtimeRunner` does that
  upstream) and the latency of one 40 ms frame plus buffering.
- **Drums:** map GM channel 10 to the four drum triggers.
- **Prompt from audio:** MusicCoCa can embed a clip of audio instead of
  text ("sound like this clip").
- **Base model:** a pack option, for machines that can run it.
- **CoreML:** [mattmireles/magenta-realtime-2-iphone](https://github.com/mattmireles/magenta-realtime-2-iphone)
  converts mrt2_small to three CoreML graphs, the way the stems model
  runs (docs/30 §Stems). It doesn't convert the prompt and note encoder
  yet. With that, the pack would need no MLX and no build.
- **macOS:** the mlx-metal wheels start at macOS 14, and slab supports
  13. MRT2 is macOS 14 or later.
